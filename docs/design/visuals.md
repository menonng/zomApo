# 좀비화 외형: 서버 리소스팩과 모델

2026-11-20. 요구: "기존 마크 몹 모델링을 가져와서 거기에 좀비 느낌을 더한다. 자연스럽게." 참고 방향은 바닐라의 원종-좀비 짝(주민 ↔ 좀비 주민, 말 ↔ 좀비 말, 낙타 ↔ 낙타 허스크, 앵무조개 ↔ 좀비 앵무조개, 피글린 ↔ 좀비화 피글린)이다.

## 0. 리소스팩: 강요하지 않는다 (2026-11-20 개정)

- 바닐라 클라이언트는 **엔티티마다 다른 텍스처·모델을 고를 방법이 없다.** 리소스팩만으로는 '크리퍼 전체'를 바꿀 수 있을 뿐 '좀비화된 크리퍼만' 바꿀 수 없다. 이건 Fabric 이든 Paper 플러그인이든 똑같다. 플러그인 서버로 바꿔도 커스텀 외형에는 리소스팩이 필요하다.
- 리소스팩 없이 하려면 **클라이언트 모드**를 깔게 해야 하는데, 그게 친구들에게 가장 큰 부담이라 서버 사이드로 정했다.
- **결정: 리소스팩은 '선택'(`require-resource-pack=false`).** 받으면 좀비화 외형이 자연스럽게 보이고, 거절해도 아래 0-2절의 **리소스팩 없는 외형**으로 플레이에 지장이 없다. 팩 호스팅·전송은 Polymer 자동 호스팅.

### 0-1. 리소스팩을 받으면 매번 로딩이 뜨나

| 단계 | 처음 접속 | 다음 접속부터 |
|---|---|---|
| 내려받기 | 한 번(수 MB, 몇 초) | **없음.** 클라이언트가 팩의 해시로 캐시해 둔다. 팩을 고쳐 해시가 바뀔 때만 다시 받는다 |
| 적용(리소스 다시 불러오기) | 있음 | **있음.** 서버 리소스팩은 접속을 끊으면 내려가므로 들어올 때마다 다시 얹는다. 작은 팩이면 2~5초 |
| 움직일 수 없는 시간 | 적용하는 동안 | 적용하는 동안. 월드에 들어가기 전 단계라 그동안 게임 안에서 공격받지 않는다 |

즉 **기다림은 매번 몇 초씩 있지만, 내려받기는 처음 한 번뿐**이다. 팩을 작게 유지하고(텍스처 위주, 1~3MB), 시즌 중에는 고치는 횟수를 줄인다.

### 0-2. 리소스팩 없는 외형 (거절한 사람 / 리소스팩 없이 운영할 때)

| 방법 | 원리 | 쓸 곳 |
|---|---|---|
| 바닐라 좀비 짝 | 엔티티 자체를 바꿈 | 호글린 → 조글린, 피글린 → 좀비화 피글린 |
| **커스텀 플레이어 머리** | 머리 아이템의 `profile` 컴포넌트에 썩은 얼굴 스킨 텍스처(모장 스킨 서버 주소)를 넣는다. 리소스팩 없이 바닐라 클라이언트가 그린다. 미리 만든 얼굴 스킨 20~30개를 한 번 등록해 두고 텍스처 값을 설정에 저장 | 머리 칸을 그리는 몹(스켈레톤 계열, 우민, 브루트)의 머리, 사람형이 아닌 몹은 디스플레이 엔티티로 등·머리에 '썩은 혹'처럼 1~2개 |
| 바닐라 갑옷 염색·장식 | 가죽 갑옷 색(녹회색), 갑옷 장식 무늬(바닐라 무늬·재료) | 사람형 몹 |
| 블록·아이템 디스플레이 | 이끼·진흙·뼈 블록 조각을 작게 붙임 | 크리퍼 등 등판, 슬라임 속 |
| 크기·파티클·소리 | `scale`, 포자 파티클, 바닐라 좀비 소리 높낮이 바꿈 | 전부 |

리소스팩을 받은 사람에게는 같은 몹이 1절의 B~E 방식으로 보인다(서버가 사람마다 다른 패킷을 보낸다. 팩 사용 여부는 접속할 때 응답으로 안다).

## 1. 몹마다 쓸 수 있는 방법

| 방법 | 원리 | 자연스러움 | 비용 | 쓸 곳 |
|---|---|---|---|---|
| **A. 바닐라 좀비 짝** | 엔티티를 바닐라 좀비 버전으로 바꾼다 | 완벽(모장 디자인) | 없음 | 호글린 → 조글린, 피글린 → 좀비화 피글린 |
| **B. 장비 레이어 오버레이** | 보이지 않는 갑옷 칸에 `equippable` 컴포넌트의 장비 에셋(리소스팩의 `equipment/*.json`)을 넣는다. 사람형 몸체 위에 한 겹 더 그려져 **애니메이션을 그대로 따라간다** | 아주 좋음 | 거의 없음 | 갑옷 레이어를 그리는 사람형: 스켈레톤·스트레이·보그드·파치드·위더 스켈레톤 |
| **C. 머리 칸 모델** | 머리 칸 아이템에 `item_model` 로 만든 썩은 얼굴·두건 모델. 머리 회전을 따라간다 | 좋음(얼굴만) | 거의 없음 | 머리 아이템을 그리는 몹: 우민(약탈자·변명자·소환사·환술사). 마녀는 확인 필요 |
| **D. 색 변형 텍스처** | 몹의 바닐라 변형 값 중 쓰이지 않는 것을 좀비화 텍스처로 바꿔 둔다 | 완벽 | 없음 | 셜커(초록 셜커 텍스처를 '부패 셜커'로) |
| **E. 블록벤치 리그** | 진짜 몹은 투명하게 두고, 블록벤치 모델을 디스플레이 엔티티 뼈대로 씌워 따라 움직이게 한다(서버 사이드 라이브러리 **Blockbench Import Library**, 26.3 빌드 있음 + Polymer) | 좋음(애니메이션 직접 제작) | **큼**: 몹 하나에 디스플레이 엔티티 6~12개, 위치 갱신 패킷 | 사람형이 아닌 몹: 거미·크리퍼·엔더맨·크리킹·슬라임·팬텀·가디언·브리즈·가스트·블레이즈·마그마 큐브 |
| **F. 공통 신호** | 포자 파티클(2초에 1개), 리소스팩 좀비 울음소리, 눈 색 | — | 아주 작음 | 모든 좀비화 몹. E 가 없는 거리·몹에서의 기본 표시 |

`scale` 속성(크기)은 바닐라 클라이언트가 그대로 그리므로 모든 방법과 함께 쓸 수 있다(예: 부패 엔더맨 1.05배).

## 2. 모델을 만드는 방법

**원종 모델을 그대로 가져와 좀비 느낌을 더한다.**

1. **텍스처**: `tools/respack/zombify_textures.py` 가 실행하는 사람의 마인크래프트 jar 에서 원종 텍스처를 읽어 1차 시안을 만든다. 채도를 낮추고 녹회색 쪽으로 돌린 뒤, 노이즈로 썩은 살(올리브)·벌어진 상처(검붉은)·포자(연두) 반점을 얹는다. 뼈 몹은 대신 살점이 붙은 뼈로. 눈 레이어는 감염된 황록색으로.
   - 저장소에는 Mojang 텍스처를 넣지 않는다. 스크립트만 있고, 결과물은 빌드 때 만들어진다(`tools/respack/out/`, 저장소 제외).
   - 시안은 출발점이다. 블록벤치에서 손으로 다듬는다(얼굴 표정, 드러난 갈비뼈, 찢어진 피부 가장자리).
2. **모양(E 방식 몹)**: 블록벤치의 바닐라 엔티티 템플릿에서 원종 모델을 불러오고, 바닐라 좀비 짝들이 하는 방식으로만 손댄다.
   - 몸 일부에 살덩이 큐브를 덧붙이거나(좀비 말의 드러난 갈비뼈처럼) 큐브를 조금 처지게 기울인다.
   - 뼈대·비율은 원종 그대로 둔다. 실루엣으로 원종을 바로 알아봐야 한다.
   - 애니메이션: 걷기·서기·공격 3개. 원종보다 약간 비틀거리게.
3. **B 방식 오버레이**: 원종 텍스처 위에 덮을 '부패 살갗' 한 장(투명한 곳이 많은 갑옷 레이어 텍스처). 갑옷 레이어는 몸보다 조금 크게 그려지므로 살갗이 들러붙은 느낌이 난다.

시제품 시안 보기: `python zombify_textures.py --preview preview.png --preview-only "skeleton/skeleton.png,creeper/creeper.png,spider/spider.png"` (왼쪽 원본, 오른쪽 시안).

## 3. 단계별 도입 (성능과 작업량)

| 단계 | 내용 | 개장 전 필수 |
|---|---|---|
| 1 | A(호글린·피글린), B(스켈레톤 계열), C(우민), D(셜커), F(전부) | ✔ |
| 2 | E: 크리퍼·거미·엔더맨 (가장 흔한 셋) | 가능하면 |
| 3 | E: 나머지 (크리킹, 슬라임, 팬텀, 가디언, 브리즈, 가스트, 블레이즈, 마그마 큐브) | 시즌 중 추가 |

**E 방식의 성능 제한** (단계 2 에서 실측해 정한다):

- 리그는 **보는 사람에게서 32블록 안**에 있을 때만 씌우고, 멀면 원종 모습 + 포자 파티클(F)로 돌아간다.
- 한 사람 화면에 리그는 **최대 24개**. 넘으면 가까운 순서대로만.
- 뼈대 위치 갱신은 2틱에 한 번, 움직이지 않을 때는 보내지 않는다.
- 좀비 떼·블러드문처럼 몹이 몰리는 순간에는 리그 상한을 12개로 낮춘다.
- 측정 도구(`tools/perf/bench.py`)에 리그 켬/끔 조합을 넣어, 서버 틱과 클라이언트 프레임(9600X·RX 9070 XT 기준)을 비교한 뒤 상한을 확정한다.

## 4. 바닐라 클라이언트에서 확인할 것 (구현 전 체크리스트)

- [ ] 장비 에셋 오버레이가 스켈레톤 계열에서 갑옷처럼 그려지는지, 갑옷 소리·방어력 없이(`equippable` 만, 속성 수정자 없음) 되는지
- [ ] 마녀 렌더러가 머리 칸 아이템을 그리는지(안 그리면 F 방식만)
- [ ] 셜커 색 변형이 엔티티 데이터로 바뀌는지, 플레이어가 염료로 바꿀 수 있는지
- [ ] 리소스팩이 원종 텍스처를 덮지 않는지(우리 텍스처는 `zomapo` 네임스페이스에만)
- [ ] 투명 상태의 원종이 그림자·화염·이름표를 남기지 않는지(E 방식)
