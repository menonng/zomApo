## 구조

### 1. 스택

| 항목 | 값 | 근거 |
|---|---|---|
| 언어 | Kotlin 2.4.x | 요구 사항. FLK 가 싣는 표준 라이브러리 버전에 맞춘다 |
| Minecraft | 26.3 → 26.4 | [README.md](../server/README.md#버전-정책) |
| Java | 25 | 26.x 요구 |
| Fabric Loader | 0.19.3 이상 | |
| Fabric API | `0.161.0+26.3` | |
| Fabric Language Kotlin | `1.14.2+kotlin.2.4.21` | |
| Gradle 플러그인 | `net.fabricmc.fabric-loom` (리매핑 없음, Mojang 이름) | 26.x 는 Yarn 없음 |
| 환경 | `"environment": "server"` | 바닐라 클라이언트 접속 |
| 설정 직렬화 | kotlinx.serialization (JSON) | |
| 의존성 버전 | `gradle/libs.versions.toml` (버전 카탈로그) | monun 의 paper-sample 과 같은 방식. 26.4 로 올릴 때 한 파일만 고친다 |

외부 런타임 의존(필수)은 Fabric API 와 FLK 뿐이다. simpleNationWar(`snw-api`)는 선택 의존이다.

**Kotlin 라이브러리는 모드 jar 에 넣지 않는다.** FLK 가 Kotlin 표준 라이브러리, kotlinx.coroutines, kotlinx.serialization 을 런타임으로 제공한다(monun 의 kotlin-plugin 이 Bukkit 에서 하던 역할). 모드마다 따로 넣으면 버전 충돌이 난다.

### 2. 서버 사이드 제약과 해법

| 하고 싶은 것 | 막히는 이유 | 해법 |
|---|---|---|
| 새 좀비 몹 | 새 엔티티 타입은 바닐라 클라이언트가 모른다 | 바닐라 엔티티 + Fabric 데이터 부착 + 장비·`scale` 속성·머리 아이템으로 외형 |
| 새 아이템(바이러스 결정, 해독제) | 새 아이템 타입도 마찬가지 | 바닐라 베이스 아이템 + `custom_model_data`(리소스팩의 아이템 정의가 이 값으로 모델을 고름)·`item_name`·`custom_data`(판별) 컴포넌트 |
| 새 상태 효과(출혈·감염·태양광 알레르기) | 상태 효과 목록은 클라이언트로 동기화되지 않는다(26.3 의 동기화 레지스트리 목록에 없음). 새 효과 번호를 보내면 접속이 끊긴다 | 효과는 서버에만 등록하고 패킷을 거른다(Polymer 상태 효과 숨김). 플레이어에게는 화면 위 보스바 한 줄에 리소스팩 비트맵 글꼴 아이콘 + 남은 시간. 바닐라 효과를 덮어쓰지 않는다 |
| 새 블록 | 블록 목록도 고정(블록 상태 번호). 새 블록을 그대로 보낼 수 없다 | ① Polymer 가상 블록: 거의 안 쓰는 바닐라 블록 상태(소리 블록의 음·악기 조합 800가지 등)를 리소스팩으로 새 그림으로 바꿔 쓴다. 부수는 시간·소리·파편·고르기(휠 클릭)는 바탕 블록을 따른다 ② 표시 엔티티 + 보이지 않는 충돌 블록: 모양은 자유, 무겁고 빛·그림자가 블록 같지 않다. 아이템은 `item_model` 로 완전히 새 그림이 된다 |
| 커스텀 인첸트 효과 | 인첸트 정의는 클라이언트로 동기화 | 정의엔 바닐라 컴포넌트만, 효과는 모드가 인첸트 유무로 처리 |
| UI | 클라이언트 화면 추가 불가 | 상자 메뉴 GUI, 바닐라 다이얼로그(입력 폼), 액션바, 보스바, 타이틀 |
| 감염 지역의 하늘·안개 색 | 리소스팩 없이 불가 | 파티클·소리·액션바로 대신. 바이옴 교체 방식은 시즌 2 후보(아래 8절) |

### 3. 모듈과 패키지

서브프로젝트 두 개로 나눈다. monun 의 speculation 이 게임 로직(`core`)과 마인크래프트 표시(`plugin`)를 나눈 것과 같은 생각이다. 26.4 로 올린 뒤에는 26.3 을 유지하지 않으므로 버전별 서브프로젝트는 만들지 않는다.

| 서브프로젝트 | 내용 | 테스트 |
|---|---|---|
| `logic` | 마인크래프트를 모르는 순수 Kotlin: 감염 레벨 식(전역 램프, 국가 열기, 정화, 개인 보정), 장비 점수, 점수 보정·농장 감쇠, 변종 가중치 추첨, 강화 확률·찬스 타임, 블러드문 웨이브 구성 | JUnit. 밀리초 단위로 돌고, 시뮬레이터 수치와 대조할 수 있다 |
| `mod` | Fabric 모드. `logic` 을 jar 안에 포함하고 엔티티·월드·GUI 를 다룬다 | 서버 게임테스트 |

```

├─ build.gradle.kts, gradle.properties, settings.gradle.kts, gradle/libs.versions.toml
├─ logic/src/main/kotlin/dev/menonng/zomapo/logic/   infection/, score/, starforce/, spawn/
├─ logic/src/test/kotlin/…
├─ mod/src/main/kotlin/dev/menonng/zomapo/
│  ├─ ZomApo.kt                     진입점, 서비스 연결
│  ├─ config/                       설정 데이터 클래스, 다시 읽기
│  ├─ infection/                    감염 레벨 계산(전역 램프, 국가 열기, 정화, 영역 판정), 둥지, 블러드문
│  ├─ conversion/                   변환 규칙(태그), 치환·감염·기수 처리, 스폰 훅
│  ├─ form/                         ZombieForm 계층: 변환형·변종의 개념(설정)과 행동(런타임)
│  ├─ ai/                           이식용 목표(goal) 래퍼: 활, 석궁, 포션 투척, 송곳니, 벽 굴착…
│  ├─ loot/                         원본 + 좀비 루트 이중 굴림, 바이러스 결정
│  ├─ stats/                        좀비 통계 SavedData, 점수 계산, 농장 감쇠
│  ├─ revenant/                     망자 좀비
│  ├─ starforce/                    강화 규칙, GUI
│  ├─ enchant/                      커스텀 인첸트 효과 처리
│  ├─ integration/snw/              snw-api 연동(선택), 통계 제공자
│  ├─ integration/map/              감염 레이어(지도 모드가 있을 때)
│  ├─ gui/                          상자 메뉴 DSL
│  ├─ command/                      관리자 명령 (Brigadier Kotlin DSL)
│  └─ util/                         틱 스케줄러, 코루틴 디스패처, 시간
├─ mod/src/main/java/…/mixin/       믹스인 (자바)
├─ mod/src/main/resources/
│  ├─ fabric.mod.json, zomapo.mixins.json
│  └─ data/zomapo/ …                태그, 루트 테이블, 인첸트 데이터팩
└─ mod/src/gametest/                서버 게임테스트
```

### 4. monun 저장소에서 가져올 패턴

[monun](https://github.com/monun) 의 공개 저장소 16개 전체 분석은 [reference/monun.md](../reference/monun.md). 대부분 Paper 플러그인이고 보관(archived) 상태다. 코드는 GPL-3.0 이므로 **복사하지 않고 설계만 참고**한다. Fabric 은 Bukkit 이벤트가 없으므로 같은 생각을 믹스인 + 부착으로 옮긴다.

| monun 쪽 | 무엇을 하는가 | zomApo 에서 |
|---|---|---|
| series-survival `Bio` | `enum Type(key, displayName, creator)` 로 생존자·좀비·슈퍼 좀비·하이퍼 좀비를 상태 기계처럼 다룬다. `onAttach/onDetach/onUpdate/applyAttribute`, 상태마다 YAML 저장 | `ZombieForm` 봉인 계층(일반·변종·치환형·감염형·망자). 같은 생명주기 훅(`attach`, `detach`, `tick`, `applyAttributes`, `save/load`)을 엔티티 부착에 묶는다 |
| series-survival `SurvivalConfig` | `@Config` 리플렉션으로 설정 필드를 자동 읽기/쓰기 | kotlinx.serialization 데이터 클래스 + `/zomapo reload` |
| series-survival `Zombie.Wand` | 아이템별 쿨다운을 틱으로 관리하고 `setCooldown` 으로 표시 | 26.x 아이템 `use_cooldown` 컴포넌트와 서버 틱 시계 |
| series-survival `HyperVaccine` | 틱마다 진행되는 연출 태스크(폭죽 → 차례로 해방) | 블러드문·둥지 파괴 연출을 틱 태스크로 |
| tap `EntityEventManager` | **엔티티 단위** 이벤트 리스너 등록(그 엔티티에 일어난 일만 받기) | 믹스인이 부착된 `ZombieForm` 의 `onHurt/onAttack/onTarget/onDeath` 로 바로 전달. 엔티티 단위 디스패치 |
| tap `Ticker` | 틱 기반 스케줄러 | 서버 틱 스케줄러 + 서버 스레드 코루틴 디스패처(`delayTicks(n)`) |
| tap `FakeEntity` | 패킷으로만 존재하는 가짜 엔티티 | 등불 인첸트의 플레이어별 발광, 경고 표시 같은 '그 사람에게만 보이는' 연출 |
| psychics `AbilityConcept` / `Ability` | **정적 설정(개념)** 과 **런타임 인스턴스** 분리. 개념은 설정 파일에서 읽고, 인스턴스는 플레이어마다 생긴다 | `FormConcept`(JSON: 체력, 속도, 크기, 장비, 점수, 레벨별 가중치) / `FormBehavior`(엔티티마다). 밸런스 조정 = JSON 수정 |
| psychics `TestResult` | 능력 사용 가능 여부를 봉인 클래스로 반환 | 강화 시도 가능 여부(재료 부족, 최대 성 등)를 봉인 결과로 |
| kommand | Brigadier 위 Kotlin DSL (`then("name" to string()) { executes { … } }`) | 작은 자체 DSL. 관리자 명령만 있으므로 가볍게 |
| invfx | 상자 GUI Kotlin DSL (Frame, Slot, Pane, List) | 강화 GUI 용 상자 메뉴 DSL. simpleNationWar 와 같은 모양으로 맞춘다 |
| tap `Ticker` 세 모드 | plank(게임 틱), precision(실제 시간, 밀린 틱 몰아서 실행), flex(실제 시간, 밀린 실행 한 번) | 몹 AI·쿨다운은 게임 틱, **블러드문 30분·06:00 재계산·망자 보호 10분은 실제 시간 기준**. 렉이 걸려도 이벤트 길이가 늘지 않는다 |
| tap `ConfigSupport` 범위 어노테이션 | 범위 밖 설정값을 잘라냄 | 설정 데이터 클래스에 범위 검증(확률 0~1, 레벨 0~5) |
| series-survival `TickTask` | 설정 파일 수정 시각이 바뀌면 다음 틱에 자동으로 다시 읽음 | `/zomapo reload` 와 함께 자동 리로드 |
| tap `TemplateSupport` | 설정 문자열의 `$이름`, `${식}` 치환 | 모든 안내 문구(액션바, 알림, lore)를 설정 템플릿으로. 문구 수정에 재빌드 불필요 |
| series-survival 진영별 `FakeEntityServer` | 생존자 머리 위 좀비 머리 마커를 **좀비 진영에게만** 보여 줌 | 망자 마커(본인·자국민만), 등불 인첸트 발광(본인만) |
| series-survival 하이퍼 좀비 | 스코어보드 팀 색으로 발광 테두리 색을 바꿈 | 알파 좀비를 전용 팀(빨강)에 넣어 빨간 테두리 발광 |
| psychics `DamageType` | 피해 종류를 보호 인첸트와 묶음 | 변종 특수 공격은 바닐라 피해 유형(투사체·폭발·마법)으로 → 보호 인첸트가 그대로 먹힘 |
| psychics `TooltipBuilder` | 제목·머리말·본문·꼬리말로 아이템 설명 조립 | 스타포스 lore, 바이러스 결정 설명 |
| psychics 자원 소유권 | 능력 인스턴스가 자기 스케줄러·가짜 엔티티·리스너를 소유하고 해제 시 정리 | `FormBehavior` 가 만든 예약 작업·가짜 엔티티를 엔티티 사망·언로드 시 함께 정리 |
| speculation `core` / `plugin` | 순수 게임 로직과 마인크래프트 표시 계층 분리, 로직은 JUnit 테스트 | `logic` / `mod` 서브프로젝트 (3절) |
| speculation `GameDialog<R>` + 코루틴 | 코어가 `suspend` 로 플레이어 입력을 요청, 표시 계층이 처리기 제공, 없으면 기본값 | 바닐라 다이얼로그를 `suspend fun <R> ask(…, timeout, default)` 로 감싸 강화 확인 등에 사용 |

### 5. 데이터 저장

| 데이터 | 위치 | 이유 |
|---|---|---|
| 변환 정보, 망자 소지품 | 엔티티 부착(저장형) | 엔티티와 함께 언로드·로드 |
| 좀비 통계 | `SavedData` `zomapo_stats` (UUID 키) | 오프라인 조회, 국가 합계 |
| 감염 상태 | `SavedData` `zomapo_infection` | 전역 램프, 국가별 일일 스냅샷, 이벤트 보정, 둥지 |
| 강화 정보 | 아이템 `custom_data` | 아이템과 함께 이동 |

`SavedData` 는 코덱으로 직렬화한다. 디스코드 봇·결산용 JSON 내보내기는 simpleNationWar 쪽 디스코드 모드가 `snw-api` 통계 제공자를 통해 가져간다.

### 6. simpleNationWar 연동

의존 방향은 **zomApo → snw-api** 한쪽뿐이다.

| 필요 | 방법 |
|---|---|
| 플레이어의 국가, 국가 목록, 영토 청크, 관계 | `snw-api` 의 `NationApi` 를 `compileOnly` 로 참조, 실행 시 `FabricLoader.isModLoaded("snw")` 확인 |
| 영토 변경 알림(접경 BFS 재계산) | `NationApi.events().onClaimChanged` |
| `/info`·국민 목록에 좀비 통계 표시 | zomApo 가 `snw:stat_provider` 엔트리포인트로 `StatProvider` 구현을 등록 |
| 망자 보호 시간의 자국민 판정 | `NationApi.sameNation(a, b)` |

simpleNationWar 가 없으면: 모든 땅을 황야로 계산하고, 자국민 판정은 '본인만', 통계는 관리자 명령으로만 본다.

### 7. 테스트

- **`logic` 단위 테스트**: 감염 레벨 식의 경계값(0·5 클램프, 솔로 상한), 점수 보정 조합, 강화 확률 표·찬스 타임, 변종 가중치 분포. 시뮬레이터([tools/sim](../../tools/sim))와 같은 입력을 넣어 같은 값이 나오는지 대조한다.
- **서버 게임테스트**: 변환 확률 경계, 루트 이중 굴림, 점수 보정, 망자 생성·회수, 강화 확률 표.
- **헤드리스 서버 기동 CI**: InfraCraft 의 modpack 워크플로처럼 실제 서버를 띄워 모드가 켜지는지 확인한다. 26.4 업그레이드 때 가장 먼저 깨지는 지점을 잡는다.
- **시뮬레이터**: 밸런스 수치를 바꿀 때 [tools/sim](../../tools/sim) 을 같이 돌린다.

### 8. 시즌 2 후보

## 좀비화 외형

2026-11-20. 요구: "기존 마크 몹 모델링을 가져와서 거기에 좀비 느낌을 더한다. 자연스럽게." 참고 방향은 바닐라의 원종-좀비 짝(주민 ↔ 좀비 주민, 말 ↔ 좀비 말, 낙타 ↔ 낙타 허스크, 앵무조개 ↔ 좀비 앵무조개, 피글린 ↔ 좀비화 피글린)이다.

### 0. 리소스팩: 필수 (2026-11-21 개정)

- 바닐라 클라이언트는 **엔티티마다 다른 텍스처·모델을 고를 방법이 없다.** 리소스팩만으로는 '크리퍼 전체'를 바꿀 수 있을 뿐 '좀비화된 크리퍼만' 바꿀 수 없다. 이건 Fabric 이든 Paper 플러그인이든 똑같다. 플러그인 서버로 바꿔도 커스텀 외형에는 리소스팩이 필요하다.
- 리소스팩 없이 하려면 **클라이언트 모드**를 깔게 해야 하는데, 그게 친구들에게 가장 큰 부담이라 서버 사이드로 정했다.
- **결정: 리소스팩은 필수(`require-resource-pack=true`).** 접속하면 받으라고 묻고, 거절하면 접속하지 않는다. 대신 **로딩 시간을 최대한 줄인다**(0-3). 팩 호스팅·전송은 Polymer 자동 호스팅.
- 아래 0-2절의 '리소스팩 없는 외형'은 팩 서버가 내려갔을 때의 비상 대안으로만 남긴다.

#### 0-1. 리소스팩을 받으면 매번 로딩이 뜨나

| 단계 | 처음 접속 | 다음 접속부터 |
|---|---|---|
| 내려받기 | 한 번(수 MB, 몇 초) | **없음.** 클라이언트가 팩의 해시로 캐시해 둔다. 팩을 고쳐 해시가 바뀔 때만 다시 받는다 |
| 적용(리소스 다시 불러오기) | 있음 | **있음.** 서버 리소스팩은 접속을 끊으면 내려가므로 들어올 때마다 다시 얹는다. 작은 팩이면 2~5초 |
| 움직일 수 없는 시간 | 적용하는 동안 | 적용하는 동안. 월드에 들어가기 전 단계라 그동안 게임 안에서 공격받지 않는다 |

즉 **기다림은 매번 몇 초씩 있지만, 내려받기는 처음 한 번뿐**이다.

#### 0-3. 로딩 줄이기

클라이언트의 '적용' 시간은 대부분 **모든 리소스를 다시 읽는 바닐라 과정**(최근 PC 에서 2~4초)이고, 우리 팩이 더하는 몫은 팩 내용에 달렸다. 그래서 무거워지는 원인을 아예 넣지 않는다.

| 규칙 | 이유 |
|---|---|
| 셰이더(코어 셰이더) 넣지 않음 | 셰이더 컴파일이 가장 느리고, 그래픽 카드마다 깨질 위험 |
| 바닐라 글꼴을 바꾸지 않음. 상태 효과 아이콘용 **작은 비트맵 글꼴 하나**(`zomapo:hud`, 9×9 그림 몇 장)만 새 이름공간에 | 바닐라 글꼴 재구성이 느리다. 작은 비트맵 글꼴 하나는 거의 공짜(2026-11-21 개정) |
| 바닐라 텍스처를 덮어쓰지 않고 `zomapo` 이름공간에만 추가 | 덮어쓰기는 아틀라스 전체에 영향, 다른 리소스팩과 충돌 |
| 텍스처 크기는 원종과 같게(16~64px), PNG 무손실 최적화(팔레트 PNG, 메타데이터 제거) | 용량 = 내려받기 시간, 디코딩 시간 |
| 소리는 꼭 필요한 것만, OGG 모노 짧게. 대부분 바닐라 소리의 높낮이만 바꿔 씀 | 소리는 용량이 가장 큼 |
| 블록벤치 리그 모델은 뼈대마다 작은 아이템 모델 하나 | 모델 수 = 로딩 시간 |
| 언어 파일 최소, 쓰지 않는 파일 빌드 때 제거 | |
| `pack_format`·`supported_formats` 를 정확히 | 맞지 않으면 '호환되지 않음' 경고 창이 한 번 더 뜬다 |
| 팩 해시(SHA-1)를 함께 보냄 | 클라이언트가 캐시를 쓰고 다시 받지 않는다 |
| 시즌 중 팩 교체는 정기 재시작 때만 | 바뀔 때마다 모두가 다시 받는다 |

목표: **팩 용량 1MB 안팎, 적용 추가 시간 0.5초 미만.** 측정: 개장 리허설 때 클라이언트 로그의 리소스 다시 불러오기 시간을 팩 있음/없음으로 비교한다.

#### 0-4. 로딩하다 죽는 일은 없나

**없다.**

1. 서버 리소스팩은 **월드에 들어가기 전 단계**(설정 단계)에서 받고 적용한다. 그동안 플레이어는 아직 월드에 없다.
2. 월드에 들어온 뒤 지형을 불러오는 동안은 바닐라가 **클라이언트가 '다 불러왔다'고 알릴 때까지 플레이어를 무적으로 둔다**(26.3 `hasClientLoaded`).
3. 그 위에 zomApo 가 **접속 보호**를 더한다: 다 불러온 뒤 10초, 또는 처음 움직이거나 공격할 때까지 몹이 그 플레이어를 노리지 않고 피해도 받지 않는다. 좀비 떼 대상에서도 빠진다.

단, 시즌 중에 팩을 '접속해 있는 사람에게' 바로 밀어 넣으면 게임 안에서 로딩 화면이 뜬다. 그래서 팩 교체는 정기 재시작 때만 한다(0-3).

#### 0-2. 리소스팩 없는 외형 (거절한 사람 / 리소스팩 없이 운영할 때)

| 방법 | 원리 | 쓸 곳 |
|---|---|---|
| 바닐라 좀비 짝 | 엔티티 자체를 바꿈 | 호글린 → 조글린, 피글린 → 좀비화 피글린 |
| **커스텀 플레이어 머리** | 머리 아이템의 `profile` 컴포넌트에 썩은 얼굴 스킨 텍스처(모장 스킨 서버 주소)를 넣는다. 리소스팩 없이 바닐라 클라이언트가 그린다. 미리 만든 얼굴 스킨 20~30개를 한 번 등록해 두고 텍스처 값을 설정에 저장 | 머리 칸을 그리는 몹(스켈레톤 계열, 우민, 브루트)의 머리, 사람형이 아닌 몹은 디스플레이 엔티티로 등·머리에 '썩은 혹'처럼 1~2개 |
| 바닐라 갑옷 염색·장식 | 가죽 갑옷 색(녹회색), 갑옷 장식 무늬(바닐라 무늬·재료) | 사람형 몹 |
| 블록·아이템 디스플레이 | 이끼·진흙·뼈 블록 조각을 작게 붙임 | 크리퍼 등 등판, 슬라임 속 |
| 크기·파티클·소리 | `scale`, 포자 파티클, 바닐라 좀비 소리 높낮이 바꿈 | 전부 |

리소스팩을 받은 사람에게는 같은 몹이 1절의 B~E 방식으로 보인다(서버가 사람마다 다른 패킷을 보낸다. 팩 사용 여부는 접속할 때 응답으로 안다).

### 1. 몹마다 쓸 수 있는 방법

| 방법 | 원리 | 자연스러움 | 비용 | 쓸 곳 |
|---|---|---|---|---|
| **A. 바닐라 좀비 짝** | 엔티티를 바닐라 좀비 버전으로 바꾼다 | 완벽(모장 디자인) | 없음 | 호글린 → 조글린, 피글린 → 좀비화 피글린 |

| **F. 공통 신호** | 포자 파티클(2초에 1개), 리소스팩 좀비 울음소리, 눈 색 | — | 아주 작음 | 모든 좀비화 몹. E 가 없는 거리·몹에서의 기본 표시 |

`scale` 속성(크기)은 바닐라 클라이언트가 그대로 그리므로 모든 방법과 함께 쓸 수 있다(예: 부패 엔더맨 1.05배).

### 2. 모델을 만드는 방법

**원종 모델을 그대로 가져와 좀비 느낌을 더한다.**

1. **텍스처**: `tools/respack/zombify_textures.py` 가 실행하는 사람의 마인크래프트 jar 에서 원종 텍스처를 읽어 1차 시안을 만든다. 채도를 낮추고 녹회색 쪽으로 돌린 뒤, 노이즈로 썩은 살(올리브)·벌어진 상처(검붉은)·포자(연두) 반점을 얹는다. 뼈 몹은 대신 살점이 붙은 뼈로. 눈 레이어는 감염된 황록색으로.
   - 저장소에는 Mojang 텍스처를 넣지 않는다. 스크립트만 있고, 결과물은 빌드 때 만들어진다(`tools/respack/out/`, 저장소 제외).
   - 시안은 출발점이다. 블록벤치에서 손으로 다듬는다(얼굴 표정, 드러난 갈비뼈, 찢어진 피부 가장자리).
2. **모양(E 방식 몹)**: 블록벤치의 바닐라 엔티티 템플릿에서 원종 모델을 불러오고, 바닐라 좀비 짝들이 하는 방식으로만 손댄다.
   - 몸 일부에 살덩이 큐브를 덧붙이거나(좀비 말의 드러난 갈비뼈처럼) 큐브를 조금 처지게 기울인다.
   - 뼈대·비율은 원종 그대로 둔다. 실루엣으로 원종을 바로 알아봐야 한다.
   - 애니메이션: 걷기·서기·공격 3개. 원종보다 약간 비틀거리게.
3. **B 방식 오버레이**: 원종 텍스처 위에 덮을 '부패 살갗' 한 장(투명한 곳이 많은 갑옷 레이어 텍스처). 갑옷 레이어는 몸보다 조금 크게 그려지므로 살갗이 들러붙은 느낌이 난다.

시제품 시안 보기: `python zombify_textures.py --preview preview.png --preview-only "skeleton/skeleton.png,creeper/creeper.png,spider/spider.png"` (왼쪽 원본, 오른쪽 시안).

### 3. 도입: 시즌 1 에 전부 (2026-11-21 개정)

A~F 를 **개장 전에 모두** 넣는다(사람형 덧씌움 B, 머리 모델 C, 색 변형 D, 블록벤치 리그 E 11종, 공통 신호 F). 예전의 '단계 2·3 은 가능하면·시즌 중' 구분은 없앴다.

**E 방식의 성능 제한** (리그를 붙인 뒤 실측해 정한다):

- 리그는 **보는 사람에게서 32블록 안**에 있을 때만 씌우고, 멀면 원종 모습 + 포자 파티클(F)로 돌아간다.
- 한 사람 화면에 리그는 **최대 24개**. 넘으면 가까운 순서대로만.
- 뼈대 위치 갱신은 2틱에 한 번, 움직이지 않을 때는 보내지 않는다.
- 좀비 떼·블러드문처럼 몹이 몰리는 순간에는 리그 상한을 12개로 낮춘다.
- 측정 도구(`tools/perf/bench.py`)에 리그 켬/끔 조합을 넣어, 서버 틱과 클라이언트 프레임(9600X·RX 9070 XT 기준)을 비교한 뒤 상한을 확정한다.

- **지금 상태**: 23종 2차 디자인의 형상·텍스처·미리보기·`.bbmodel`. 남은 일은 블록벤치에서 열어 확인·손질, 리소스팩 내보내기(뼈대마다 아이템 모델, 장비 에셋, 머리 아이템 모델, 셜커 텍스처), 서버 쪽 리그 붙이기.
- **움직임**: 리그 애니메이션을 키프레임으로 따로 만들지 않고, **바닐라 모델이 걷기·공격 때 뼈대를 돌리는 식을 서버에서 그대로 계산**해 뼈대 표시 엔티티에 보낸다. 원종과 똑같이 움직이고 좀비다운 비틀거림만 조금 더한다.
- **발광**: 포자 자루·독샘·떠다니는 조각·송진·눈꽃·영혼 불꽃처럼 빛나는 덧붙임은 따로 뼈대로 두고 그 표시 엔티티의 밝기를 최대로 고정한다. 원종 텍스처 위의 빛나는 균열은 밝은 색으로만 표현한다(텍스처 일부만 발광시킬 수는 없다).
- `.bbmodel` 좌표: 바닐라 모델 공간에서 x → −x, y → 24 − y(z 축 180° 회전), 뼈대·큐브 회전은 x·y 부호 반전. 블록벤치로 연 확인은 아직 안 함.

### 3-2. 디자인 원칙과 몹별 콘셉트 (2026-11-21 2차)

1차본은 모든 몹에 같은 피·뼈 덧붙임을 한 가지 색으로 붙여 식상했다. 2차 원칙:

- **좀비화 = 피가 아니다.** 바닐라의 좀비 짝(익사체는 바다 청록과 해초, 허스크는 마른 모래, 좀비화 피글린은 드러난 두개골)처럼 **서식지에 맞는 색 변화 + 큼직한 대표 형태 몇 개 + 손으로 배치한 무늬**로 간다. 절지동물은 체액, 식물성 몸은 균류, 엔드 몹은 공허, 네더 몹은 영혼 불·진홍 균류·잿불.
- **명암과 질감**: 덧붙임 하나에 색 띠 5~6단계. 빛은 위·앞-왼쪽, 윗면이 가장 밝고 아랫면이 가장 어둡다. 둥근 것(알·자루·버섯갓)은 구체 명암과 반사광, 색이 바뀌는 곳은 베이어 디더링. 1~2픽셀짜리 부품은 쓰지 않고 형태가 읽히는 크기로 만든다.
- **기믹 신호**: 덧붙임은 그 몹의 기믹을 알려 준다(좀비 '몹 좀비화' 3절의 '모델 신호').
- **바꿀 수 없는 것**: 스켈레톤 계열·브루트(B)와 일리저·마녀(C)는 바닐라 클라이언트가 같은 텍스처로 모든 개체를 그리므로 **몸 텍스처를 바꿀 수 없다.** 장비 레이어 덧씌움(머리·몸통 자리만)과 머리 아이템으로만 꾸민다. 리그(E)와 셜커 색 변형(D)만 몸 텍스처까지 새로 그린다.
